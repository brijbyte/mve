Install

pnpm add @brijbyte/mve react

Usage

Editor is a controlled component: pass value and update it from onChange. The theme stylesheet is optional but gives the mve-* classes their colours. 

import { useState } from "react";
import { Editor } from "@brijbyte/mve";
import { javascript } from "@brijbyte/mve/languages";
import "@brijbyte/mve/theme.css";

// Build once: a new Language object means a full reparse.
const JS = javascript();

export function App() {
  const [value, setValue] = useState("const answer = 42;");
  return <Editor value={value} onChange={setValue} language={JS} />;
}

Languages

Built-in languages come from a separate entry so unused grammars stay out of your bundle, and each one is also its own entry for lazy loading. 

import { css, javascript, json } from "@brijbyte/mve/languages";

javascript();      // plain JavaScript
javascript("jsx"); // with JSX
javascript("ts");  // TypeScript
javascript("tsx"); // TypeScript + JSX
json();
css();

// Each grammar is also its own entry, so it can be a lazy chunk.
// This page does exactly that: no grammar ships until it is needed.
const ts = await import("@brijbyte/mve/languages/javascript")
  .then((m) => m.javascript("ts"));

Custom languages

A Language is a Lezer parser plus optional highlighter and refine. Anything from the @lezer ecosystem plugs in. 

import type { Language } from "@brijbyte/mve";
import { parser } from "@lezer/python";

// Any Lezer parser works. Tokens are classed by the default
// highlighter unless you pass your own `highlighter`.
const python: Language = { parser };

// Optional: adjust classes from token text.
const withBuiltins: Language = {
  parser,
  refine: (classes, text) =>
    classes === "mve-v" && text === "self" ? "mve-self" : classes
};

Theming

Colours are CSS variables, light by default. Dark applies under prefers-color-scheme: dark or inside a .mve-dark ancestor; .mve-light forces light. The buttons above toggle exactly that. 

/* Override any --mve-* variable; light values live on :root. */
:root {
  --mve-k: #8250df;
  --mve-s: #0a3069;
}

/* Force a palette on a subtree, or let prefers-color-scheme decide. */
.mve-dark { --mve-bg: #0d1117; }
.mve-light { --mve-bg: #ffffff; }

/* The root element carries .mve; size and font are yours. */
.mve {
  font-family: ui-monospace, monospace;
  font-size: 14px;
  padding: 0.75rem;
}

Props

Remaining props spread onto the root div, so className, style and event handlers work as usual. 

interface EditorProps extends HTMLAttributes<HTMLDivElement> {
  value: string;                      // controlled text
  onChange?: (value: string) => void; // fires on every edit, undo and redo
  language?: Language | null;         // null renders plain text
  indent?: string;                    // inserted on Tab, default two spaces
}

Compared with react-simple-code-editor

Why not Prism + react-simple-code-editor

It is a quarter of the size, so the question is fair. What the extra bytes buy:

  • Correct tokens. Lezer parses the language; Prism matches regular expressions. Regex highlighting guesses at anything context-dependent: / as division or regexp, <T> as generic or JSX, expressions inside template literals, nested comments and strings. A parser gets these right and recovers from incomplete code as you type.
  • Per-edit cost. Prism re-tokenises the whole document on every keystroke and react-simple-code-editor re-renders the whole highlighted block. Here the browser edits the line, Lezer reparses only what changed, and only lines whose tokens changed are swapped: on a 20k-line file a keystroke touches one line and stays around 11 ms.
  • One DOM layer. react-simple-code-editor keeps a transparent textarea over a highlighted pre and relies on both staying pixel-aligned; wrapping, scrolling, fonts and IME each have a way to break that. This editor edits the highlighted DOM directly: one element, native selection, native find-in-page, one textbox for assistive technology.
  • Richer classes. Parameters, definitions, calls, property access, operator kinds, JSX tags versus components and built-in types are distinct classes, so themes can look like an editor's rather than a blog's code block.
  • The Lezer ecosystem. Any @lezer grammar, including the ones CodeMirror uses, plugs in as a Language. The syntax tree is there for folding, indentation or linting later.

Pick Prism + react-simple-code-editor when the code is short, a wrong token now and then is fine, and every kilobyte matters. Pick this when the document can get long or the highlighting has to be right.

Editing behaviour

  • Enter keeps the current line's indentation.
  • Tab inserts indent. Paste inserts plain text.
  • Undo and redo (Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, Ctrl+Y) are handled by the editor.
  • Work per keystroke is proportional to the edit: only touched lines are read back, reparsed and re-rendered.
